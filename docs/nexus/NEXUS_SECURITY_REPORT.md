# JARVIS NEXUS — Security Audit & Cryptographic Specification
**Document Version:** 1.0.0  
**Security Level:** Production Android-to-Android Cryptographic Architecture  

---

## 1. Cryptographic Primitives

### 1.1 Device Identity (Hardware-Backed)
- **Key Store:** Android Keystore (`AndroidKeyStore`)
- **Key Algorithm:** Elliptic Curve (EC) with Curve secp256r1
- **Signature Algorithm:** `SHA256withECDSA`
- **Protection:** Private keys are generated inside the device secure hardware (TEE / StrongBox) and never exported or written to plaintext storage.

### 1.2 Ephemeral Pairing Authentication
- **Pairing Code:** 6-digit cryptographically pseudo-random number generated by `java.security.SecureRandom`.
- **Time-to-Live (TTL):** 5 minutes (300,000 ms).
- **Single-Use Invalidation:** Upon successful validation, the pairing code is immediately consumed and purged from memory.
- **No Hardcoded Secrets:** Static fallback codes (such as "888888" or "123456") have been strictly eliminated from production code.

### 1.3 Transport Encryption & Integrity
- **Symmetric Cipher:** AES-256-GCM (`AES/GCM/NoPadding`)
- **IV Length:** 12 bytes (96 bits) randomized per packet via `SecureRandom`
- **Authentication Tag:** 128 bits GCM tag providing authenticated encryption with associated data (AEAD)
- **Data Integrity:** Cumulative SHA-256 hash computed over streamed binary chunks during file transfers. Final file commitment requires matching remote Host digest verification.

## 2. Attack Mitigation

| Threat Vector | Mitigation Strategy |
|---|---|
| **Replay Attacks** | Every command contains unique `nonce` and expiration timestamp (60s TTL). |
| **Eavesdropping (LAN)** | AES-256-GCM encryption with dynamic IV prevents packet sniffing on shared Wi-Fi networks. |
| **Relay Tampering (Internet)** | Blind forwarding on Node.js relay server: ciphertext is end-to-end encrypted between paired phones. The relay holds zero plaintext keys. |
| **Unauthorized File Alteration** | SHA-256 checksum mismatch triggers immediate temporary file deletion without committing to storage. |
| **Silent Device Control** | Host owner must approve incoming connections via modal dialog and grant granular capability toggles. |
| **Malicious Code Injection** | JSON RPC commands strictly dispatch allowlisted application actions; shell execution and dynamic class loading are prohibited. |
